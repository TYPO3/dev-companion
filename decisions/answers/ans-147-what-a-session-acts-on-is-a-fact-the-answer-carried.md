# D-ANS-147 — What a session acts on is a fact the answer carried

**Every surface two sessions credit reported something about their own world
inside the answer, and both skipped the step that told them to go and fetch one
themselves.**

The two halves are one boundary, and the second half is what the gate question
has been waiting on.

## Evidence

- `feedback/2026-09-03-235407`, a v14 project session. What it credits:
  `typo3_project_describe`'s commands block with the `runs` mark, which stopped
  it reaching for a static analyser the repository does not declare; the
  resolved set list per site, which answered the user's opening question
  outright; two documentation pages fetched back by URL and read whole, so no
  key name was guessed; and `typo3_commit_message_guide` reporting a subject 15
  characters over and declining to shorten it.
- `feedback/2026-09-03-105707`, a core patch session in another checkout. What
  it credits: the TCA reference page that contradicted the code it had just
  read, which turned the patch's justification around; a whole document read by
  `documentId`, which sent the changelog file to the oldest branch of the
  `Releases:` trailer instead of to `main`; the commit guide naming the lines a
  bugfix takes and saying that which of them carry the defect is the caller's
  reading; and `reviews[]` on the backlog rows, which is what kept it off two
  issues under active review.
- Every one of those is a fact from the caller's own world — this repository's
  declared commands, this site's sets, this manual's page, this issue's open
  changes — delivered in an answer the session already had.
- Both sessions skipped a step that asked them to fetch one. The first says the
  deprecation sweep was skipped and calls it "luck rather than judgement"; the
  second is `feedback/2026-09-03-105724`, where a named `omittedHints` id was
  never fetched across about a hundred further calls.
- The three surfaces that state their own limit are among what is credited by
  name: the check the repository does not declare, the branches the caller has
  to verify, and the summary the guide will not reword. The second session
  writes it out — an answer that says what it cannot know is worth more than one
  that guesses.

## Decided

- Nothing changes here. A strength is evidence about a boundary rather than a
  decision to confirm — `D-FBK-018` — and this is the boundary: what is acted on
  arrives in the answer, and what is prescribed is what gets dropped.
- Both feedback are answered by this entry and archived by the commit that
  writes it, and the card of each goes with them.
- The second half is recorded against `todo/waiting/T-260817-0cb1`, which has
  been asking since 2026-08-17 whether a workflow closes on a gate. It is a
  third sighting of a prescription dropped without anything noticing, and the
  recommendation there is unchanged.

## Assumed

- That these two sessions are not simply reporting the surfaces they used most.
  Both name calls they made and did not credit, which is the only thing
  separating the two readings.

## Wrong if

- A session credits an answer that carried no fact of its own — a checklist
  item, a prescription — as what changed its work. Then what pays is not the
  fact but the wording, and the gate question is about wording too.
- A prescribed step turns out to be dropped no more often than a fact is
  ignored, which would make the second half of this a pair of sightings rather
  than a pattern.
