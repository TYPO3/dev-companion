# D-ANS-147 — What a session acts on is a fact the answer carried

**Every surface two sessions credit reported something about their own world
inside the answer. Both skipped the step that told them to go and fetch one
themselves.**

The two halves are one boundary, and the second half is what the gate question
has waited on.

## Evidence

- `feedback/2026-09-03-235407`, a v14 project session. What it credits.
  `typo3_project_describe`'s commands block with the `runs` mark, which stopped
  it from a reach for a static analyser the repository does not declare. The
  resolved set list per site, which answered the user's first question outright.
  Two documentation pages fetched back by URL and read whole, so it guessed no
  key name. And `typo3_commit_message_guide`, which reported a subject 15
  characters over and declined to shorten it.
- `feedback/2026-09-03-105707`, a core patch session in another checkout. What
  it credits. The TCA reference page that contradicted the code it had just
  read, which turned the patch's justification around. A whole document read by
  `documentId`, which sent the changelog file to the oldest branch of the
  `Releases:` trailer instead of to `main`. The commit guide, which named the
  lines a bugfix takes and said that which of them carry the defect is the
  caller's read. And `reviews[]` on the backlog rows, which kept it off two
  issues under active review.
- Every one of those is a fact from the caller's own world, in an answer the
  session already had. That is this repository's declared commands, this site's
  sets, this manual's page, this issue's open changes.
- Both sessions skipped a step that asked them to fetch one. The first says it
  skipped the deprecation sweep and calls it "luck rather than judgement". The
  second is `feedback/2026-09-03-105724`, where a named `omittedHints` id never
  got a fetch across about a hundred further calls.
- The three surfaces that state their own limit are among what the reports
  credit by name. Those are the check the repository does not declare, the
  branches the caller has to verify, and the summary the guide will not reword.
  The second session writes it out — an answer that says what it cannot know is
  worth more than one that guesses.

## Decided

- Nothing changes here. A strength is evidence about a boundary rather than a
  decision to confirm (`D-FBK-018`), and this is the boundary. What a session
  acts on arrives in the answer, and what a prescription asks for is what drops
  out.
- This entry answers both feedback and the commit that writes it archives them,
  and the card of each goes with them.
- The second half stands against `todo/waiting/T-260817-0cb1`, which has asked
  since 2026-08-17 whether a workflow closes on a gate. It is a third instance
  of a prescription dropped and nothing that noticed, and the recommendation
  there stays.

## Assumed

- That these two sessions do not simply report the surfaces they used most. Both
  name calls they made and did not credit, which is the only thing that
  separates the two accounts.

## Wrong if

- A session credits an answer that carried no fact of its own — a checklist
  item, a prescription — as what changed its work. Then what pays is not the
  fact but the wording, and the gate question is about wording too.
- A prescribed step turns out to drop out no more often than a session ignores a
  fact. That would make the second half of this a pair of instances rather than
  a pattern.
