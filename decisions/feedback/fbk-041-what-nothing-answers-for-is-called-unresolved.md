# D-FBK-041 — What nothing answers for is called unresolved

**`bin/cli unresolved:list` reads out the three states nothing may fail on, and
`backlog` retires as a word this repository uses.**

One word named three different sets, which is the failure `AGENTS.md` names
under "one thing, one word". It sat on the word that names the report every
session opens with.

## Evidence

- The three sets, all present on this entry's day. The union the command printed
  — an open requirement, one that is `not guarded`, a decision whose **Wrong
  if** nobody has been back to. The first of those alone, which is what the
  layout line in `AGENTS.md` called the backlog. And the feedback nobody has
  judged, which is what the `status` description of `typo3_feedback_list` called
  it — a schema a client reads.
- The word was already right in the code. `Upkeep\Unresolved` carries the
  definition of the union in its own docblock, and the command that prints it
  was the only thing still called `backlog`.
- The rename reaches nobody outside this checkout. `backlog:list` appears in no
  file under `knowledge/`, `skills/` or `readme.md`, so no installed client and
  no published skill names it.

## Decided

- The word retires rather than narrows to one of the three. Keeping it for the
  open requirements alone would leave a second name for a subset of what one
  command already prints.
- A feedback nobody has judged is an open feedback, and the tool schema a client
  reads describes it that way.
- Records in `decisions/` keep the word where their own prose used it. Only the
  command pointer changed, because a name a reader would type has to work. An
  account of what somebody thought carries a date and stays as it stands.

## Assumed

- That `unresolved` reads as the union to somebody who meets it in the command
  list and never opens the class behind it. No measure covers this; the word
  came from the code, which already used it for exactly that set.

## Wrong if

- The word comes back. Nothing catches a noun, so a session that writes
  "backlog" again for any of the three is what would show the retirement did not
  take.
- The union turns out to be two readings. The requirement side and the decision
  side print in one report and nobody has asked for them apart. A second command
  would mean the union was never the thing.
- A reader takes `unresolved:list` for a check that fails, which is exactly what
  [`D-FBK-001`](fbk-001-the-backlog-is-read-out-rather-than-enforced.md) says it
  may never be.
