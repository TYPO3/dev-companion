# R-ANS-037 — An answer says how to read the current version rather than naming one

**An answer that touches a version outside TYPO3 says where to read the current
release rather than names one. That is node, a GitHub Action, DDEV, a library.**

A version in a hint is right on the day somebody writes it and wrong afterwards
in silence. That is why a count of something that grows is not written down here
either. What the answer carries instead is the place the caller reads it from.
That is the runtime's own release schedule, the action's repository, the
registry the library goes to.

What a TYPO3 line requires is a different statement and stays. That is a floor
the core declares. The statement carries it as data rather than in the sentence.
A caller told what the core requires has learned something that does not move
under them.

`R-COD-004` is the same demand on this repository, and `R-SKL-029` on a
published skill.

## From

The maintainer's instruction of 2026-08-29. Nobody had read the corpus for
version numbers of this kind, so what it cost stayed unmeasured.

## Held by

`not guarded`. A session ran the sweep on 2026-09-01 over `knowledge/` and found
nothing to rewrite: no answer offers an outside version as the one to adopt.
What it did find is four kinds of number that stay. That is what a TYPO3 line
declares as a floor, and a version quoted out of a tool's own output. It is a
format's version such as XLIFF, and a phrase a query matches on such as "PHP 8.4
syntax". A check would report all four. To tell them from a recommendation is a
read rather than a pattern, and that is why nothing holds this.

`task-intents.json` is what the demand already looks like where an answer meets
it. The answer about `typo3/coding-standards` names no release and says to let
the solver pick one.
