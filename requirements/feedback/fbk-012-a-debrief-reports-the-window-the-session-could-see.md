# R-FBK-012 — A debrief reports the window the session could see

**The debrief prompt asks for the part of the session the agent can still read.
So the agent does not report what its window lacks as what did not happen.**

The transcript is the whole of what makes a debrief worth more than an
impression. An agent whose context begins at a compaction summary has none for
the first half of its own run. Asked which skills activated and which calls it
made, it answers for the session from the part it can see.

## From

`feedback/2026-08-01-003736` (2026-08-01), which withdrew the "never activated"
claim of three earlier notes of the same session. Its ground was that its window
began at an anchored summary — `D-FBK-023`.

## Held by

- The prompt and what comes back are both not guarded. It is prose in
  [documentation/records/asking-for-a-debrief.rst](../../documentation/records/asking-for-a-debrief.rst),
  which somebody pastes by hand into a session this repository cannot read, and
  nothing here runs over either half.
