# R-KNW-050 — A preview answer names what the preview draws from

**A backend preview answer names the field kinds the preview draws its content
from. It says the preview is what tells two instances of one element apart.**

Where the template registers, what it receives and what the header already draws
are three answers about everything except the output. A preview that reads
"Testimonials element" satisfies all three. The demand they leave open is the
one an editor pays for.

The answer names the field kinds one at a time, because that is what decides a
line of the template. Those are the text columns, file relations, link fields, a
select's chosen item and the children of an inline relation. "Show a summary" is
advice and changes nothing about what somebody writes.

It carries no version of its own. The evidence is `theme_camino`, which ships on
14 alone. What a preview owes the editor is not a property of a major. How a
field is reachable is the half that binds, and `R-KNW-041` carries it.

## From

A session that built a TYPO3 14 testimonials element and shipped a preview that
named the element. It had followed every preview statement the corpus had. The
rule it lacked came from the user instead (2026-08-01).
