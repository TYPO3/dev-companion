# SITE-13 — A second site in an installation that already has one

**Environment:** `E-SITE` 14.3 with `typo3/theme-camino` required, one site on
`base: /`, and the sitepackage a `SITE-12` run produced · **Contract:** `open`
**Held by:** `HintsTest::whichOfTwoCollidingSiteBasesWinsIsStated`,
`HintsTest::whereASiteNobodyWroteCameFromIsStated` and
`HintsTest::whatANotFoundMeansOnceASiteAnsweredIsReached`, which hold that the
three statements this case turns on exist. That a session reaches them is **not
guarded**. That it says what the second site owes `theme_camino` is **not
guarded** either.

`SITE-11` and `SITE-12` build the first site. This case starts where they stop.
The installation renders, the editors work in it, and a second organisation
wants a site of its own.

The starting state is one site on `base: /`, seven pages, and fifty content
elements. Its configuration depends on a project sitepackage, and that
sitepackage requires `theme_camino`. So the second site meets a package somebody
else already wrote.

**The first site's bare base is the trap, and it bites quietly.** A base that
names a host wins the site match on that host alone. The first site therefore
keeps every host nobody claims, and a reader who expects it to go dark is wrong.
What breaks is the link: a link from the second site into the first resolves
against the wrong host and answers 404. The session that meets it owes the user
a decision rather than a repair.

A root page created in the backend makes the core write a site nobody asked for.
The identifier is `autogenerated-<uid>-<md5 of that uid>` and the base is a
sub-path. A session that creates the page and then writes the configuration by
hand leaves two sites where it wanted one.

A set that depends on the sitepackage inherits what the sitepackage depends on.
Where that is `theme_camino`, the second site is tied to the theme of one
release line, and no file says so.

**The prompt is wrong on purpose.** It calls the first site's brand blue, and
that brand is `#06603f`. Every answer the installation holds contradicts the
brief. This case measures when the session says so, not whether.

**Run 2026-10-31:** two runs of `claude-opus-5-5` from one commit, one with this
server and one without. Both gave the second site a host of its own, left the
first site on `base: /`, and kept both sites answering. Both wrote a second set
that depends on the sitepackage, and neither named `theme_camino`. The run with
the server made three calls to it. It built first, then reported the brief's
wrong colour and asked. The run without the server stopped before it built,
offered three readings, and waited. It wrote the brand as three typed colour
settings an editor changes; the other run wrote it as a path to a stylesheet a
developer writes. The run with the server met the autogenerated site and deleted
it. The run without it found the broken link into the first site and reported
it. Both handed over a URL the environment's certificate does not cover.

> The county library is getting its own website, in this same installation.
>
> It needs a start page, an opening-hours page and an events page. The editors
> are the same team as the council's, so they should work with the elements they
> already know. The library's brand is green rather than the council's blue, and
> its footer names the library rather than the council.
>
> There is no real domain yet. Put it on a `library.` host of this DDEV project
> for now, and tell me which URL to open.
>
> The council site is live. It has to keep answering on the address it answers
> on today.

**What the agent needs from this server**

- Which site answers a request where two bases fit it, and that a base naming a
  host wins on that host alone.
- That the core writes a site configuration of its own for a page created at the
  root.
- That a set depends on what the set it builds on depends on.
- Where a setting's definition belongs and where its value belongs, as in
  `SITE-09`.

**What has to come out of it**

- Both sites answer. The first keeps the address it had, and the second answers
  on its own.
- The answer says which site answers a request, rather than leaves the reader to
  find that out.
- The second site reuses the sitepackage. A copy of the package fails this.
- The brand is a setting an editor changes. Its definition stands in the set and
  its value stands per site, and a value only a developer writes fails this.
- The answer names what the second site owes `theme_camino`.
- The session says that the brief's colour contradicts the installation, before
  it builds on either reading.
- The URL the answer hands over opens in a browser.

**How it fails**

- The second site claims the host the first one serves while the first stays on
  `base: /`. The first site goes dark, and the 404 reads like a slug problem.
- A page created at the root leaves an `autogenerated-<uid>-<md5>` site behind.
- A link from the second site into the first, built from a base with no host,
  answers 404.
- The sitepackage copied for the second site, so two packages drift apart.
- The brand behind a stylesheet only a developer writes.
- `theme_camino` inherited through the new set and never named.
- A URL the environment's certificate does not cover, handed over as the result.
