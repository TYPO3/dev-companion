# Write what verifies a change against the installation

Ladder step 1a: the probe reaches nothing, and the session reported five
verifications that read the producing tool's own output — a guard that never ran
printing that it had, a regex that edited nothing counting the list it iterated,
a `UID=` assignment bash ignores, a rename called complete on a green suite.
What worked each time was a reader with no part in the writing. Establish what
the installation can be asked after a structural change — which CType values
exist against which are declared, which tables no TCA declares, what
`sys_refindex` holds for a table nothing registers — and write the hint. The
second half is the same shape from the other end: where an entry states
something per file, per table or per row, it says so, because a repair takes the
unit its knowledge is stated in and this session fixed one TCA file of five.
