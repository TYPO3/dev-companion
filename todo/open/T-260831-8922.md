# Write what drawing a content icon set takes

Ladder step 1a: the server says whether an identifier is registered and whether
one resolves, and has nothing between the two — the session was handed
typo3.github.io/TYPO3.Icons by the user for the grid, the palette and the
stroke, applied it uniformly, and produced seven framed rectangles nobody can
tell apart at 16 pixels. So the document is about the set and not only the icon:
the distinguishing feature carries the meaning, the core's own content icons
differ in silhouette, and the check is rendering the set side by side and naming
each without its label. Establish it against the icon repository and the core's
own set before writing `any/icons/drawing-a-content-icon`. The second step is
`typo3_icon_lookup` saying what a registered identifier is already bound to, so
borrowing a core CType's icon is visible without knowing the naming scheme.
