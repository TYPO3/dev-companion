# The accessor hint is reachable from the template and not from the class

`fluid-object-access` states the resolution order, the shadowing and the naming
rule, and carries the exception string in its `appliesTo`. What decides whether
a caller reaches it is the domain: measured on 2026-09-01, the message "The
argument "each" was registered with type "array", but is of type "boolean"" with
a `.html` path reaches the hint first and with a `Classes/Dto/Result.php` path
reaches nothing at all, because `Domains` places a query carrying no Fluid word
in `php` and the hint is `fluid` alone.

That is `D-KNW-075`'s third **Wrong if** measured rather than reported: the
session that writes `hasItems()` is standing in the PHP class, and the hint is
filed where the template is read. Two levers, and the choice is what this todo
settles: the hint carries `php` beside `fluid`, or `Domains::KEYWORDS` gains the
ViewHelper error phrasings. The first widens what a PHP question answers with,
the second reweighs every query — the file says so where the testing phrasings
were added.

Both touch `src/`, so neither is a change the judging run may make. Read
`knowledge/hints/fluid.json`, `src/Knowledge/Domains.php` and `D-KNW-078`, which
kept the record hint in `php` alone for the mirror-image reason.
