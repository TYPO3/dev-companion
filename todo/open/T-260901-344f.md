# An annotation that repeats what the compiler knows hides what it is wrong about

Ruled a rule on 2026-09-01, and a general one: annotate where inference cannot
reach and nowhere else. `backend-typescript` already says the neighbouring half
— `no-inferrable-types` is off, so the linter pushes nobody in this direction
and imitating a neighbour is a diff nobody asked for.

What is missing is the procedure with teeth, which the report states and this
corpus does not: a compiler error appearing after an annotation is removed is
evidence about the annotation before it is a reason to restore it. The report
carries three defects found that way in the core. Establish them against
`.checkouts/` — a callback annotated over a narrowed `querySelectorAll`, a
number assigned to `innerText`, a property the interface spells differently —
and write the rule beside the two switched-off rules rather than as a fourth
hint about TypeScript style. The `@lit/task` case belongs with
`backend-lit-task`, which already owns that class.
