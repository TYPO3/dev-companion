# Where the rule against empty() holds, and what enforces it there

The maintainer ruled on 2026-09-01 that this is a rule rather than taste, and
named its source: the strict rules for PHPStan. That source is not the core's —
`phpstan/phpstan-strict-rules` is in no covered checkout's `composer.json` and
in no `Build/phpstan/*.neon`, and the core's own analysis runs at level 5 with
four rules of its own. So a statement saying the core forbids `empty()` would be
wrong, and one saying nothing leaves a reviewer's finding unstated.

The step is to establish where it does hold: which package rule rejects the
call, what its message is, and whether a project this server answers for runs
it. Then a hint in the PHP conventions, scoped rather than core, stating the
substitution per expected type — the report has the list — and that a nearby
`empty()` is not licence to write another. `core-static-analysis` is where the
core's own four rules already sit.
