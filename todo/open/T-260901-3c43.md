# empty() answers for six values and the code cannot say which one it meant

The maintainer ruled on 2026-09-01 that this is a rule, and on 2026-09-02 that
it stands on what `empty()` is: a falsy test rather than a comparison against an
expected type. `0`, `''`, `'0'`, `null`, `false` and `[]` all satisfy it, so a
condition written that way states none of them and a defect in any one of them
reads as the intended case. The strict rules for PHPStan reject the call for
that reason; they are corroboration rather than the source, and the rule holds
where nothing runs them.

The step is the statement in the PHP conventions: the reason first, then the
substitution per expected type — `($x ?? false)`, `($x ?? null) !== null`,
`$x !== []`, `$x !== ''` — because which one is right depends on the type and
the report has the list. Say the tension with it, which the report asks for and
this repository already writes elsewhere: `empty()` is everywhere in the core
and its own analysis does not reject it, so one nearby is a finding at a path
being changed rather than a local style to keep. Verify what that analysis does
run before saying so — `.checkouts/main/Build/phpstan/phpstan.neon` is level 5
and four rules of its own, and `core-static-analysis` is where those are stated.
