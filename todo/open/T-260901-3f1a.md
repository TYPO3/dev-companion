# Give the record lookup an environment that can answer it

The tool is built and its central case — the rows of a project's own table — is
recorded nowhere. Neither recording environment can produce it: `E-SITE` has no
extension of its own, so every table is refused there, and the fixture
installation below `.fixtures/installation` has the extension but no TYPO3 to
open a connection with — its recorded answer is `installation-not-answering`.
The queries themselves were run by hand against the running `E-SITE` 14.3 on
2026-09-01 — the grouped count, a filter on a string column, and the rows with
the label resolved from the table's own ctrl — so what is missing is the
environment rather than the code. Either give
`bin/cli environment:create E-SITE` an extension of the project's own with a
table and rows in it, or say in `documentation/records/` that this one answer is
held by `RecordLookupTest` alone and why. `FixtureTest` skips the two calls that
reach the database by their labels today, which is the second place that
decision is written.
