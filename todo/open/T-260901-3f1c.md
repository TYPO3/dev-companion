# Say what the order established before the checkout is opened

`skills/base.md` accounts for the order at the end, where the report names every
step it did not reach. Nothing asks for that account at the front, so what the
four fixed calls established stays unwritten until the answer is. Add one step
between the order and **Then** read the checkout: the session writes out the
version, the packages in scope, the checks the repository declares, and the
steps it discharged with what discharged them — before the first file is opened.
`REVIEW-01`'s first criterion already grades that block, and its run shows a
session producing it out of one skill's wording rather than out of the base, so
a body that does not happen to say it is held to nothing. Hold the step to what
the four calls answered: a block that restates the reading is a second report,
and every published skill carries this file.
