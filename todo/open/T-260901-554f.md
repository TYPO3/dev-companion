# A patch is shaped for the diff somebody reads, not for the file it leaves

Ruled a rule on 2026-09-01, and one that holds for code in general rather than
for the core alone. Nothing below `knowledge/` or `skills/` states it: not the
patch development skill, not the review skill, and no hint.

Two halves, and they go to different places. The authoring half is a property of
the finished patch — edit rather than rewrite, keep the formatting that is
there, and prefer the expanded array because one key per line is what makes the
next diff narrow. The review half is a constraint on the reviewer: an
observation about structure is a comment and not an edit, which is the same
boundary `feedback/2026-09-01-210110` reports from the other side and which the
chain card carries. Read `skills/typo3-core-patch-development/SKILL.md` and
`skills/typo3-core-patch-review/SKILL.md`, and
`documentation/contributing/writing-a-skill.rst` before writing into either.
