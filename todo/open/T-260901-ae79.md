# The half of "just do the work" that is about somebody else's decision

The preference itself is the client's and this server states nothing about it —
the reporting session said so, and the maintainer's ruling on 2026-09-01 covered
the rules beside it rather than this one.

What is left is the boundary the same session found by crossing it: proceeding
with an agreed step is not licence to change a decision the author already made,
and it reported restructuring a namespace, making a class final and changing
accessor visibility on somebody's own patch. `feedback/2026-09-01-210110` is
that event from the review side and its card carries the chain; the question
here is whether a brief for `changeType="audit"` says the same thing in general
— an unrequested change to an existing decision is reported rather than made.
Judge it against what `typo3_task_guide` already returns for an audit before
adding anything.
