# A review reads what is stacked on the change before calling its shape a defect

The session reviewing core change 94652 reported four structural findings and
all four were refuted by the change above it in the chain: the one-class
subnamespace, the non-final class, the public service and the protected
accessors were groundwork. `typo3_gerrit_lookup` had already answered the chain
in the session's first call, and nothing told it what that key is evidence for.

Nothing in `skills/` names it — no skill mentions a chain except the asset build
one, about something else. The step is a step in the review skill and in the
audit brief: where a change carries a chain, read the file lists of what is
stacked on it before judging structure, API surface or test coverage, report the
shapes a follow-up explains as questions to the author, and say so where the
change under review is the bottom of one, because rebasing it obliges the rest.
`documentation/contributing/writing-a-skill.rst` is the rule for the skill half.
