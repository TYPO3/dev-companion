# A test says which case it holds, and the issue number lives in the trailer

Ruled a rule on 2026-09-01, without exception: a test comment describes the case
under test, never "regression test for #N". `core-tests` states the naming and
the fixtures and says nothing about what a test's comment or its method name
carries.

The step is the statement beside those: the method name says what holds
(`subSchemaLabelIsUsedWhenTypeValueIsSet`), the comment says which path is
exercised and why it matters, and the issue number is already in the `Resolves:`
trailer and the changelog file name — which is the argument that it is not owed
a third place. Verify the shape against the core's own tests in `.checkouts/`
before writing it, because a corpus statement about how the core writes tests is
held against the core.
