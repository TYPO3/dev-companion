# What an exact-string assertion is worth, and where that statement belongs

Ruled on 2026-09-01 as the one the maintainer left open: the rule holds, and
where it goes is undecided. A partial match on sanitiser output hides an escape,
an attribute order or a namespace change, so `SvgDocument` and `SvgSanitizer`
output is pinned whole with `assertSame`.

What decides the home is the boundary the report already found: the same
reasoning does not reach markup carrying a cache buster, which icon markup does,
so an exact assertion there pins a value that moves for unrelated reasons. That
makes it a rule about output a pipeline fully determines rather than about SVG,
and the question is whether `core-tests` states it as one or the security hints
state it for the sanitiser. Read both, and the SvgDocument tests in
`.checkouts/`, which are where the practice is either already followed or not.
