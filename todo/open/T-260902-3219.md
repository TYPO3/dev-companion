# The component catalog carries no data attribute a component's module reads

Taken on, `D-ANS-139`. The catalog answered three questions right off classes
and sub-components and cost the session two silent browser failures where the
contract was an attribute: `data-on-change`, which only `EXT:redirects`' own
module implements, and `data-bs-content` on a modal that reads `data-content`.

First step: establish whether the attributes a component's own module reads are
derivable from the installed backend sources the catalog already parses for
classes. The session found the modal's set by grepping `dataset\.` out of the
built file, which says they are in there and not that a parser finds them
cleanly. Where they are, the field is the same kind as `customProperties` and
carries the same boundary: what the installed backend declares, never what an
extension adds.

Where they are not derivable, the answer is what the catalog says about the
attributes rather than the attributes themselves, and that is a different entry.
