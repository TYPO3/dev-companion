# What a Configuration/Backend/Modules.php resolves to, without a cache flush

Taken on, `D-FBK-055`, which carries the boundary and what is assumed about it.
Five registration mistakes in one session were each caught by an installation
that had already been rebuilt.

First step is the identifier half and it stands on its own: given the file, say
which `parent`, `iconIdentifier` and labels domain it names that this
installation does not have. All three fail when a user opens the module and none
of them when the file is read, and each is resolvable through calls this server
already makes.

The resolution half — the route path per entry, whether an entry gets routes at
all, where it lands among its siblings — waits on that one. It re-implements
what `ModuleRegistry` does, and `D-FBK-055` records that as the thing to be
shown worth the copy rather than assumed.
