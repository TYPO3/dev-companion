# Whether a quoted operand in a Fluid condition is a literal

The boundary this feedback reports is written down as `D-FBK-054` and needs
nothing further. What is left is its one knowledge-shaped tail, and it is a
claim about Fluid this repository cannot settle: that
`condition="{a} === '{b}'"` never matches because the quoted operand is a
literal, where `{a} === {b}` does.

The core writes the unquoted form — `beuser`'s Online template and `backend`'s
SiteConfiguration overview both compare two variables that way, and no core
template was found writing the quoted one. That is what the core does rather
than what Fluid does, and the difference is the whole question.

Fluid is not in this checkout and the core checkouts ship no vendor directory,
so the first step is `typo3_documentation_lookup`, or the parser read from an
installation that has it. Where it holds, it is a statement on
`fluid-conditions-and-arrays`, whose existing quoting statement is about the
attribute's own delimiters and not about this.
