# typo3_record_lookup counts one value at a time where a group would answer once

The session that filed the strengths behind `D-FBK-054` made thirteen counted
calls to establish one distribution, because `where` takes exact equality: one
call per status, then one per empty column. It says six of the thirteen would
have been one call grouped by a column, and that the counts-only mode is what
made thirteen affordable at all.

Queued rather than closed because it moves a declared input schema. What it
takes is a way to ask for a count per distinct value of one column, beside the
`where` that already narrows — the shape `typo3_schema_lookup` already knows,
which is where the column list comes from.

What it is worth is measured rather than assumed: thirteen calls became six on
one session's reading, and no other session has asked for it.
