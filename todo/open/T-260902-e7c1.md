# typo3_task_guide names no rule for a change that ends in a backend UI

Step 3, routing. The guides a session needs arrive as a field on
`typo3_project_describe`, at the start, before there is a task to match a `when`
clause against; by the moment the browser was needed that list was hundreds of
turns back, and `typo3_rule_lookup` was called zero times in a session that
wrote its own throwaway spec fifteen times.

`typo3_task_guide` already names the skills and the hints that match a task, and
`guides` came back empty for `changeType="feature"` on a backend module. Make it
name the rules the same way. `any/testing/browser-check` is the case to hold it
by: a change that ends in a backend UI is exactly what it is for, and it matched
nothing.

The other half of the feedback is done: the backend-module skill names that rule
at its "Prove it by opening it" step since 2026-09-02, which reaches a session
already in that workflow. This is what reaches one that is not.
