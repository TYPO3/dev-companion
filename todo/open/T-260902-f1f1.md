# One name per concept across the tool parameters

Read on 2026-09-02 over every `inputSchema()`: `open` enumerates the Forge
backlog as an enum and filters the Gerrit search as a boolean, while Gerrit
enumerates with `backlog`; the comments come back as `notes` (default `all`) on
Forge and `messages` (default `none`) on Gerrit; `changeType` is lowercase
`bugfix|feature|cleanup|…` on `typo3_task_guide` and `BUGFIX|FEATURE|TASK|…` on
`typo3_commit_message_guide`, and the brief sends its caller to the guide that
rejects the value; free text is `query`, `queries` or `task` depending on the
tool; `version` is a release prefix on `typo3_changelog_lookup` and the
extension's own number on `typo3_ter_lookup`; `targetVersion` defaults to the
declared majors on four tools and to the installed version on six, and is
required with no default on `typo3_documentation_lookup` and
`typo3_permalink_lookup`. Every one of these moves a declared input schema, so
the step is a decision first: which name wins per concept (the rule in AGENTS.md
is the one somebody outside this checkout can see), whether the old spelling is
accepted for a release, and what `D-ANS-053` said about aliases. Then one commit
per concept, with the skills and `knowledge/server-scope.json` that spell the
argument.
