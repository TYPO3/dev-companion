# Rename typo3_configuration_lookup's path to configurationPath

`D-ANS-137`'s third **Wrong if** fired on 2026-09-04: a fourth argument name
covers two concepts. `path` is a file path in a repository on
`typo3_gerrit_lookup` and `typo3_translation_domain_lookup`, and `paths` is file
paths on the three tools that take it — so unqualified `path` means a file
everywhere except `typo3_configuration_lookup`, where it is a slash-separated
path into `TYPO3_CONF_VARS`. That is the same shape as the `version` collision
the entry renamed `extensionVersion` for.

The step is `configurationPath`, which `Typo3Runtime::configuration()` already
calls it on the way to the probe, so only the tool's own surface moves: the
input schema, the echoed value in the answer, the description, and every place
this repository writes the argument down — `ToolCalls`, the recorded page, the
skills and `knowledge/`. No alias, which is what the entry decided for the other
three.

What it turns on and nothing here settles: whether a fourth rename on the same
surface is worth what it costs a caller who pinned a commit. The entry's own
answer for the first three was yes, on a 0.x package whose readme says the
shapes can move, and the maintainer took each of those. Put it before the
rename rather than after it.
