# Write the stale-rebase page and give the checkout skill its chain branch

Write `knowledge/documents/core/contribution/rebasing-a-stale-patch`, verifying
each step against `.checkouts/`: the commits `main` landed on every path the
change touches since its base, then — for each file the change rewrites or
deletes rather than edits — whether `main`'s change to it survives in the
replacement, then the public and protected members the change removes against
the callers left in the tree, then the suites covering the rewritten paths and
not only the changed ones. That fourth step is what a merged one-line fix moving
into a new file evades: git reports no conflict, because the files differ. Then
give `typo3-core-patch-checkout` the chain section `D-SKL-093` decides, routed
at the page, and say in its stopping rule that the rule exists to stop a session
authoring on an absent author's behalf, so it is spent where the author is the
requester. `SkillTest` is where the section is held. One more step belongs on
the page, from the third feedback: whether the committed JavaScript is still
consistent after the rebase, which `git log --oneline BASE..origin/main` on the
source and on its committed output settles without running `checkGruntClean`
over a tree holding a half-finished rebase.
