# Say what the prose a core patch carries owes, and route a writing task at it

Write the rule a caller gets before the text exists: what a code comment, a test
docblock and a changelog entry in a TYPO3 core patch have to read like. The
eleven rules the second feedback offers are the starting list and not the answer
— five of them are already this repository's own prose rules, so weigh each
against what a reviewer actually rejected rather than pasting the block, and
keep the worked before-and-after pairs, which are what make a rule actable. The
core's own `AGENTS.md` carries one sentence on when to write a comment, so check
what it says before writing over it. Then route it: a `changeType` that writes
files should reach it from `typo3_task_guide`, which is a
`knowledge/task-intents.json` entry rather than a change to the tool.
`D-DOC-068` has the evidence and what it decided against.
