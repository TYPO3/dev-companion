# The capabilities on initialize say what the server honours

Decide what `initialize` declares, and write the decision. The SDK's own
detection in `Mcp\Server\Builder` declares `logging`, `completions` and
`resources.subscribe: true`. The server sends no `notifications/message` and no
`notifications/resources/updated`, and it answers `completion/complete` with an
empty list. The 2026-07-28 revision deprecates logging, and a new implementation
does not add it. Two ways in. `Builder::setCapabilities()` declares tools,
resources and prompts, and keeps the extensions of `D-ANS-163`. Or completion
providers on the `commit_message` prompt make `completions` true, because
`keyword` and `workflow` take closed sets. The detection is the SDK's main path,
so the decision names which way in this server takes and why.
`documentation/server/initialize.rst` prints the capabilities and follows the
change.
