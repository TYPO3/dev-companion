# f:format.raw around a ViewHelper unescapes what the ViewHelper escaped

The REVIEW-01 run of 2026-10-28 dropped a stored XSS in `site-events`. It
cleared `{header -> events:format.highlightWords()}` because Fluid escapes the
children of a ViewHelper. In `Partials/ContentElements/Header/Header.html` that
call stands inside `<f:format.raw>`, and the judge rendered
`<img src=x onerror=alert(1)>` unescaped against the installed Fluid. The run
before it had found and rendered the same XSS. Nothing in `knowledge/` says that
`f:format.raw` around a nested ViewHelper hands its output on raw;
`security-sinks` names `f:format.raw` as a sink but not this path. Verify the
rendering on every covered line in `.checkouts/`, state it in the Fluid or
security hint, and hold it with a test that a query in the run's words reaches.
