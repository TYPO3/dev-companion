# Nothing shows yet whether a design conversion needs a skill of its own

Four greenfield runs of 2026-10-28 built a sitepackage from a static design in
`/home/lina/projects/typo3/projects/jambo-design`. The weakest, in
`jambo-pickle`, pasted it in. Its header partial opened a second
`<!DOCTYPE html>`, `<head>` and `<body>`, and the page template hardcoded six
service tiles and three notices behind `<f:if condition="{data.uid} == 1">`.

What the server now says about it:

- The `sitepackage` intent matches the words a newcomer writes: "static design",
  "html design", "html mockup", "templates into typo3", "design into typo3",
  "build this site in typo3", "own theme".
  `HintsTest::aNewcomersDesignReachesTheHintsOnConvertingIt` holds three such
  sentences to it.
- The intent's checklist routes to the new hint `sitepackage-from-a-design` and
  to `content-model-vs-markup`.
- `typo3-sitepackage-development` has a section *Convert a design*. Its render
  step 6 counts one `<html>`, one `<head>` and one `<body>` per response. It
  also names the direction of the repair, and forbids
  `config.disableAllHeaderCode` as a way to meet the count.
  `SkillTest::theSitepackageSkillConvertsADesignAndCountsTheDocument` holds
  that.

The step that remains is the open question: does converting a design earn a task
skill of its own? Every conversion failure of 2026-10-28 came from a run with no
skill loaded. So nothing shows that `typo3-sitepackage-development` fails at it,
which `D-SKL-035` demands before a new skill.

Run `SITE-10` forward in `E-SITE` with a static design handed in and the skill
loaded. The case's prompt hands in no design today, so the run needs a variant
of the prompt, or a contract case of its own beside `SITE-10`. Read the
delivered page for the document count and the blocks that repeat. Where the
package still comes out pasted, that run is the baseline for a skill. Where the
section is enough, the repository stays one skill smaller.

A relaunch has an argument of its own that this run cannot make. An agency gets
a new design and a sitepackage that already exists, and no task skill owns that
today. Decide it on the run rather than on the argument.

The read of 2026-10-29 established what the run has here. `E-SITE` 14.3 stands
below `.environments/e-site-14.3` of the main checkout, and `.session-command`
launches a client non-interactively. `/home/lina/projects/typo3/projects/` does
not exist on this machine. The baseline without the skill is already on record.
`jambo-pickle` ran in opencode with no skill published, which
`feedback/2026-10-28-163000-a-client-reached-the-server-with-no-task-skill.md`
reports. So the one run still owed is the one with the skill loaded.

The findings behind this are in
`feedback/2026-10-28-162800-a-new-project-gets-no-version-and-no-install.md`
and the two beside it.

The maintainer answered on 2026-10-29: (b). Write a static design in this
repository, beside a contract case of its own, and run `SITE-10` with it. The
session that writes it knows the failure shape, so the design stays an ordinary
small site: a header, a navigation, a page of tiles and a footer. It names no
TYPO3 idiom and carries no hint of what a conversion owes. Grade the run blind,
as `D-EVI-013` asks, three times.
