# Nothing tells a sitepackage task that a design is converted, not pasted

Four greenfield runs of 2026-10-28 built a sitepackage from a static design in
`/home/lina/projects/typo3/projects/jambo-design`. The weakest of them, in
`jambo-pickle`, pasted the design in. `Resources/Private/Partials/Page/Header.html`
opens a second `<!DOCTYPE html>`, a second `<head>` and a second `<body>`, and
`Footer.html` closes them, so the delivered page carries two documents. The
browser lifts the content out of the structure the stylesheet targets, and
nothing reports an error: the page answers 200 and the stylesheet answers 200.
`Templates/Page/Default.html` also hardcodes six service tiles and three notices
in Fluid behind `<f:if condition="{data.uid} == 1">`, so an editor cannot change
a notice, add a service or correct a date.

The rule for the second half is already here. `content-model-vs-markup` says a
page that arrived as one element was pasted rather than modelled. Its
`appliesTo` fires on the words of somebody who already has the problem —
"editors cannot edit this", "raw markup", "CType html". The `sitepackage` intent
routes to the six sitepackage hints, the focus contrast and the render proof,
and to none of this. So the task that creates the problem never meets the rule
that names it.

Three steps, the first two small:

1. Route the `sitepackage` intent to `content-model-vs-markup`. A block that
   repeats in a design is a content element with fields, not Fluid markup.
2. Say in `typo3-sitepackage-development` what converting a design means: the
   skeleton belongs to the page object and a partial is a fragment; the
   navigation is a menu processor rather than a list of page uids; assets go
   through `includeCSS` and `f:uri.resource`; the design's second page is the
   second page layout. Give the render step a check that the delivered page
   holds one `<html>`, one `<head>` and one `<body>`, because F9 passes every
   other check there is.
3. Then settle the open question: does converting a design earn a task skill of
   its own? The evidence of 2026-10-28 does not decide it. Every conversion
   failure came from a run with no skill loaded, so nothing here shows that
   `typo3-sitepackage-development` fails at it, which is what `D-SKL-035`
   demands. Run `SITE-10` again with the design handed in and the skill loaded.
   Where the package still comes out pasted, that run is the baseline for a
   skill. Where the section is enough, the repository is one skill smaller.

A separate skill has an argument of its own that this run cannot make: a
relaunch hands an agency a new design and a sitepackage that already exists, and
no task skill owns that today. Decide it on the run rather than on the argument.

and the two beside it.
