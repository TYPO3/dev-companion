# a record for one client hides the absent skills from another

Queued, step 2 of the ladder: `Installer::ABSENT` exists, and the record of a
different client kept it from the session. `D-DIS-034` holds the judgement. The
priority is `normal` because the failure is silent: the session got no workflow,
and nothing told it so.

The next step: establish the `clientInfo.name` each client in
`Installer::AGENTS` sends at `initialize`, from each client's source or a logged
handshake. Then send `ABSENT` where the recorded clients do not include the
connected one. A request handler of this server's own can do that, through the
SDK `Builder`, which takes one. A name nobody has established keeps today's
answer.
