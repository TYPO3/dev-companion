# The task guide names a skill without the resource it can be read from

Judged on 2026-10-29 as step 4 of the ladder, wording. `D-DIS-034` holds the
evidence under **Measured in opencode on 2026-10-29**. opencode 2.1.4 hands the
model `ABSENT`, and four runs without skill files read no `typo3://skill`
resource. One of them called `typo3_task_guide`. Its line that names the skill,
`TaskGuide::SKILLS_OWNING`, says "load it where this project has it installed"
and names no place that a project without skill files can load it from.
`SKILLS_IN_ORDER` says the same.

1. Make both lines name `typo3://skill/<name>/SKILL.md` as the way in where the
   project has no copy. This is a change to `src/`, so it gets the review that
   `documentation/records/judging.rst` asks for. Correct the assumption in
   `D-SKL-013` that a name the project has not installed costs nothing. Bring
   the recorded answers in `documentation/server/tools/typo3_task_guide.rst` in
   line.
2. Run the measurement again. Use opencode on `opencode/big-pickle` in a bare
   extension with a `composer.json`, an `opencode.json` entry for this server
   and no skill files. Give it the content element task. The fix holds where a
   session that calls `typo3_task_guide` then reads the `SKILL.md`. Archive the
   feedback in the commit that shows that.
3. Three of the four runs did not call `typo3_task_guide` at all and went to
   `typo3_rule_lookup`. Step 1 does not reach those runs. Count them again in
   the step 2 run. Where most runs still skip the guide, write that as a gap of
   its own beside this card.

The priority is `normal` because the feedback reports a site that served an
exception, and these runs show the same gap.
