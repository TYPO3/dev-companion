# Let environment:create seed the camino content

`SITE-12` runs against an installation that already renders, and
`theme_camino` ships the content that makes one. `bin/cli environment:create`
installs the base distribution, which does not carry that package. So the case
names steps somebody carries out by hand, in a repository that makes its own
environments.

1. Read `Environments::DRIVERS` and the `setup` call beside it. The command
   builds the composer and setup steps in one place.
2. Require `typo3/theme-camino` before the setup runs. The setup imports the
   content of a package that is already active, so the order decides whether
   any content arrives. `--distribution` is for a package that is not active
   yet, and it reports that it had no effect otherwise.
3. Set the imported site's `base` to `/`. The shipped configuration carries
   `base: /camino/`, so the site answers under a path and the project root
   gives a 404.
4. Read the frontend after the build. A measured run on 2026-10-30 gave 7 pages
   and 50 content elements, and every page answered 200.
5. Decide whether the seed is a flag or the default. An environment nothing
   asked to seed is the one `SITE-10` and `SITE-11` need, so the flag is the
   safer half of that choice.
6. Say in `SITE-12` that the environment command makes the installation, and
   take the hand-run steps out of the environment line.

`D-EVI-006` holds one installation per covered version, and a seeded one is
still that. `D-EVI-004` holds the other half: the environment is never the
subject of a recorded review, so what camino ships states the installation and
judges nothing about it.
