# What a registration file resolves to, beyond the identifiers it names

The identifier half is done: `typo3_backend_module_lookup` takes a `file` and
says which `parent`, which `iconIdentifier` and which `labels` it names that
this installation does not have, without a cache flush and without the file
being installed. The labels resolve to the XLF behind the reference and to the
trans-unit the module title is read from, which is `mlang_tabs_tab` behind an
`LLL:` reference and `title` behind a translation domain. The file is read as
text and nothing in it is executed, so a value a constant or a variable computes
is reported as unread rather than followed.

What is left is the resolution half: the route path per entry, whether an entry
gets routes at all, and where it lands among its siblings. It is what the
question above waits on, and nothing else about it is open — the shape it would
take is written in `D-FBK-055`.
