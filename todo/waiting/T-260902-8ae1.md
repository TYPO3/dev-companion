# What a registration file resolves to, beyond the identifiers it names

The identifier half exists. `typo3_backend_module_lookup` takes a `file` and
says which `parent`, which `iconIdentifier` and which `labels` it names that
this installation does not have. It does so without a cache flush and without an
install of the file. The labels resolve to the XLF behind the reference and to
the trans-unit the module title comes from. That is `mlang_tabs_tab` behind an
`LLL:` reference and `title` behind a translation domain. The tool reads the
file as text and executes nothing in it. So it reports a value a constant or a
variable computes as unread rather than follows it.

What remains is the resolution half. The route path per entry, whether an entry
gets routes at all, and where it lands among its siblings. It is what the
question above waits on, and nothing else about it is open. The shape it would
take stands in `D-FBK-055`.
