# Decide what a Claude Code session reads of an answer

`D-EVI-011` measured on 2026-09-17 that Claude Code hands the model the data
half of every answer and drops the text. opencode does the reverse. So the text
half reaches no Claude Code session, and that is the half this repository writes
the emphasis and the caveats into. The data half costs 8,535 tokens where the
text costs 7,010, for `typo3_hint_lookup` on one query.

Three ways stand open, and each costs something:

- **Keep both halves as they are.** `R-ANS-002` already demands that everything
  a caller needs is in the data. The cost is the 22 percent and every sentence
  in the text a Claude Code session never reads. Nothing changes.
- **Make the data half carry less.** `tools:measure` prints the data half per
  tool, worst first, and a field nobody composes on is the cheapest thing to
  take out. The cost is a read of each schema for what a caller composes on.
- **Answer the client by name.** The `initialize` request carries
  `clientInfo.name`. The server could leave `structuredContent` out for a client
  that drops the text. It would keep it for one on the TypeScript SDK, which
  refuses an answer without it. The cost is a branch on a client name, a second
  answer shape to test, and a schema that is declared and unmet for one client.

`bin/cli tools:tokens` measures any of them once built. The step after the
answer is the change it names, on `src/` and on the schemas, which
[judging.md](../../documentation/records/judging.rst) puts on the reviewed side.
