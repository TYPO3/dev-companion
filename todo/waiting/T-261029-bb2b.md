# Measure whether a hint this server delivers reaches the result

Two runs of 2026-10-29 read the hints they needed and built the package the
hints describe against. Fable fetched `translation-domain` by id and wrote 29
labels in the long form. Opus fetched `installation-setup` by id and named the
account `admin`. The route works, and nothing here measures the step after it.

1. Hold the two pairs with a forward run before changing a statement. Run
   `SITE-11` from a pristine greenfield directory and record, per hint, whether
   the session fetched it and whether the artifact obeys it. The transcripts of
   both runs are the model for what to extract.
2. Read `feedback/2026-08-25-105324-task-guide-returned-a-large-brief-that-changed.md`
   beside this one. It proposed the same mechanism in August and nothing has
   measured it. Judge the two together, because its suggestion is a smaller
   brief and this card's is a repeated statement.
3. Test repetition first, because it is the cheapest change. The guide answers
   once and the work runs hundreds of calls. Add the hint id to the checklist
   item that names the moment the file is written, and measure the same two
   pairs again.
4. Write a name the caller chooses into the `installation-setup` example.
   `TYPO3_SETUP_ADMIN_USERNAME=admin` is the name a scanner tries first. Add
   that the account name and the password change before the site is public.
5. Settle the contradiction between that entry's checklist items 1 and 2. Item
   1 tells the session to state a password it chose, item 2 tells it to keep
   the value out of the shell history. Where a person is at the keyboard the
   session hands over `backend:user:create` and learns no value, and item 1
   holds for the unattended case.
6. Give `site-error-handling` a route. It reached neither session and stood in
   no `omittedHints` list, so neither was told the statement exists.
7. Say in `new-project-line` that the package set is a default and not a
   question. Name `beuser` and `setup`: without them every account change
   needs a shell, because `backend:user:create` is the route that stays open.
8. Read `tca-core-palette` against the `sitepackage` and `content-element`
   intents. Neither session fetched it, and the Opus package writes four
   columns into `$GLOBALS` that reach no form.

The judging step comes first, as `documentation/records/judging.rst` says. The
feedback stays open until the commit that ships the last of these archives it.
