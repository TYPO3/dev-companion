# Repair what installation-setup says about the administrator account

The entry's worked example names the account `admin`, its checklist item 1
contradicts item 2, and item 1 rests on a lock-out that cannot happen. Two
runs of 2026-10-29 took the name and put an invented password on a command
line.

1. Write a name the caller chooses into hint [14] of `installation-setup` in
   `knowledge/hints/configuration.json`. The example demonstrates how DDEV
   carries a variable, and it loses nothing by dropping `admin`.
2. Condition checklist item 1 in `knowledge/task-intents.json` on the
   unattended case. Where a person is at the keyboard the session hands over
   the command and learns no value.
3. Replace item 1's lock-out justification. Verify against `.checkouts/` that
   `backend:user:create` carries `--admin` on every covered major, and that it
   prompts where no option supplies a value.
4. Add the handover routes: `ddev ssh` for a prompt, and `web_environment` in
   `.ddev/config.local.yaml` for a value that must arrive unattended. Say that
   the generated `.ddev/.gitignore` excludes that file and not `.ddev/.env.web`.
5. Add one statement that the account name and the password both change before
   the site is public. Nothing in the entry says it today.
6. Hold the repair with a test. No example below `knowledge/` may write
   `TYPO3_SETUP_ADMIN_USERNAME=admin`, which a check over the hint texts can
   read.
